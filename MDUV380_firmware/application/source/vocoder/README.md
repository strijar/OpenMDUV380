# Cortex-M4 source vocoder

`vocoder_thumb.S` contains the binary-derived Thumb-2 DSP implementation and
constant tables (172 recovered function bodies). It is compiled directly by
GCC's assembler, not generated by compiling the portable C DSP implementation.
No prebuilt library, binary include, or external firmware image is required.

`vocoder.c` retains the existing public API, state handling, frame packing and
FEC. Its two DSP calls use the internal declarations in `vocoder_asm.h`.
`portable_initial_state.c` and the two state `.inc` files supply the initial
encoder/decoder states. `vocoder.h` and the surrounding audio adapter are unchanged.

CMake explicitly builds these two C files and `vocoder_thumb.S` for all platform
presets, using the project's Cortex-M4 Thumb-2 hard-float ABI. The normal linker
script collects `.text*` and `.rodata*`; no fixed codec addresses are reserved.
The assembly has no `.org` directives and uses symbolic branches, pointers,
literal loads and jump-table offsets. The grouped sections require four-byte
alignment and must remain within instruction reach. Relocation is at link time,
not after copying a linked image to a new address.

The API consumes 160 PCM16 samples at 8 kHz per frame, with 7-byte packed frames
or 9-byte FEC frames. State is global: calls must be serialized and
`vocoder_init()` resets both directions. No dynamic allocation is needed.

Build with the existing CMake presets or the root Makefile. The source core has
passed binary differential tests under QEMU (1,000 sequential synthetic frames,
178 speech frames, and 255 unpack lengths). Firmware linkage does not replace
on-radio RX/TX, execution-time and task-stack high-water-mark testing.
